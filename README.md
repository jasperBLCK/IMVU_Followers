# IMVU Scripts + Web Manager

Скрипты для авто-подписок / отписок в IMVU и современный веб-сайт для удобного
управления ими: дашборд аккаунта, превью подписчиков цели, живой лог с
прогрессом и ETA.

Веб-часть — **минималистичный чёрно-белый интерфейс** с отдельной страницей
входа и двумя режимами доступа: **аккаунт** и **гость**.

## Что внутри

| Файл | Назначение |
|------|------------|
| `app.py` | Веб-менеджер (FastAPI + uvicorn): сессии, роли, API + раздача статики |
| `storage.py` | SQLite-хранилище (`data.db`): настройки, состояние эфира, треки |
| `radio.py` | Радио-движок: проверка mp3, длительность, синхронный mp3-поток |
| `static/` | Фронтенд: `login.html` (вход), `app.html` (консоль), `radio.html`, `live.html`, `style.css`, JS |
| `imvu_client.py` | Клиент IMVU API: логин, профиль, подписки, друзья, топ-подписок, фоллоу/анфоллоу, аналитика, чат комнаты (REST-часть) |
| `imq_client.py` | Клиент IMQ (WebSocket): живой чат комнаты — подписка, чтение и отправка реплик |
| `imvu_follow.py` | CLI авто-подписок (данные входа из переменных окружения) |
| `imvu_unfollow.py` | CLI авто-отписок (в т.ч. только от невзаимных) |
| `search_id.js` | Букмарклет для поиска ID пользователя (теперь необязателен) |
| `docs/imvu_api.md` | Карта REST API IMVU: эндпоинты, формат ответов, аутентификация, что ещё можно построить |
| `docs/imq.md` | Протокол IMQ (WebSocket): вход в комнату, подписка, чтение и отправка реплик чата |

## Веб-менеджер (рекомендуется)

```bash
pip install -r requirements.txt
python app.py
```

Открой http://localhost:5000 — попадёшь на **страницу входа**. Доступны два режима:

### Гость (только чтение)
Нажми **«Войти как гость»** — без логина. Можешь пробить любой аккаунт по нику
или ID и увидеть публичную стату: число подписчиков/подписок, онлайн, страну,
пол/возраст, VIP/AP-статус, дату создания и превью подписчиков. Подписки и
отписки в гостевом режиме недоступны.

### Аккаунт (полный доступ)
Введи логин/пароль IMVU и нажми **«Войти»**. После входа открывается консоль:

1. **Профиль** — аватар, подписчики/подписки, дата создания, статусы.
2. **Пробить аккаунт** — то же, что у гостя, плюс кнопки **подписаться /
   отписаться** прямо на найденного пользователя.
3. **Исключения** — добавь людей, от которых **нельзя отписываться**;
   массовый анфоллоу их пропустит. Можно вбить ник/ID вручную **или открыть
   список друзей**, отметить нужных (с фильтром по имени / «только онлайн» /
   «выделить всё») и добавить их пачкой.
4. **Топ-5 подписок** — кого из тех, на кого ты подписан, читают больше всего:
   рейтинг по числу подписчиков (user ID + количество).
5. **Цель и лимиты** — массовая подписка на подписчиков цели или отписка
   (в т.ч. только от невзаимных), с прогрессом/ETA/цветным логом.
6. **Аналитика отношений** — посчитать взаимных / фанатов / невзаимных.

В превью подписчиков цели есть **фильтр по имени и сортировка по подписчикам**.

Настройки и состояние эфира хранятся локально в SQLite-базе `data.db`
(файл в `.gitignore`, в репозиторий не попадает; старые `settings.json` и
`uploads/live/live.json` мигрируют автоматически при первом запуске).

## Что нового по сравнению со старой версией

- **Страница входа + роли**: отдельный экран авторизации, режимы **аккаунт** и
  **гость** (гость — только просмотр статы по нику).
- **Минималистичный UI**: чёрно-белая тема, аккуратная типографика,
  svg-иконки, всплывающие уведомления, живой журнал задач.
- **Исключения для отписок**: вайтлист пользователей, которых анфоллоу не
  трогает — с быстрым выбором из списка друзей (чекбоксы, фильтр, массовое
  добавление).
- **Топ-5 подписок по подписчикам**: рейтинг самых «крупных» аккаунтов из твоих
  подписок.
- **Фильтры**: поиск/сортировка в превью подписчиков и в списке друзей.
- **Аналитика отношений**: взаимные / фанаты (подписаны на тебя без ответа) /
  невзаимные.
- **Расширенный профиль**: страна, пол/возраст, VIP/AP/creator, дата создания.
- **Резолв ника в ID** через `GET /user?username=...` — больше не нужен букмарклет.
- **Надёжность**: ретраи на обрывах сети и грамотный backoff при rate-limit
  вместо фиксированного `sleep(10)`.
- **Прогресс**: скорость, ETA, счётчики ошибок/пропусков, прогресс-бар.

## Радио · музыка

Страница **«радио»** (`/radio`, файл `static/radio.html`) — твой эфир:

- **Мой эфир (трансляция)**: войди в панель аккаунтом, загрузи mp3 в эфир —
  получишь две уникальные ссылки: страницу `/live/<токен>` для браузера и
  **прямой mp3-поток** `/live/<токен>/stream` (как Icecast-радио) — его можно
  вставить в игру/плеер, звук включается сразу. Все слышат один и тот же
  момент плейлиста синхронно. Треки хранятся на сервере (`uploads/live/`,
  в `.gitignore`), поэтому эфир работает только там, где запущен `app.py`
  (локально или VPS) — на GitHub Pages его нет.
- **Заявки из интернета**: поле «найти песню» на странице радио или команда
  `!радио название песни` в чате комнаты (там же `!радио стоп`) — сервер
  находит песню (YouTube через `yt-dlp`) и транслирует её в эфир напрямую,
  без скачивания; после песни эфир возвращается к плейлисту. Для заявок на
  сервере должны быть установлены `yt-dlp` и `ffmpeg`
  (Windows: `winget install yt-dlp.yt-dlp Gyan.FFmpeg`, потом перезапустить
  терминал и сервер).
- **GitHub Pages**: страница полностью статическая — workflow
  `.github/workflows/pages.yml` публикует её на Pages при пуше в `main`
  (включи Pages в настройках репозитория: Settings → Pages → Source →
  **GitHub Actions**).

## CLI-скрипты

Данные входа берутся из переменных окружения (в коде их больше нет):

```bash
# подписки на подписчиков цели
IMVU_USERNAME=you IMVU_PASSWORD=secret IMVU_TARGET=kilka00192 python imvu_follow.py

# отписки (только от невзаимных)
IMVU_USERNAME=you IMVU_PASSWORD=secret IMVU_NON_FOLLOWERS=1 python imvu_unfollow.py
```

Доп. переменные: `IMVU_MAX`, `IMVU_DELAY`.

## Дёшево хостить (лимит ~$2)

Приложение без внешней базы (SQLite-файл) и без сборки — почти ничего не стоит:

- **Бесплатно:** запусти `python app.py` локально.
- **~$0–2/мес:** любой дешёвый VPS / free tier (Fly.io, Render free,
  Oracle Always Free). Для прода: `uvicorn app:app --host 0.0.0.0 --port $PORT`
  (один воркер — состояние задачи хранится в памяти процесса).

Порт настраивается переменной окружения `PORT` (по умолчанию `5000`).
